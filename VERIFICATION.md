# Проверка 0.3.1-beta — полный экран и возврат за две минуты

## Исправление ошибки запуска

По фото пользователя версия 0.3.0 падала при обращении к контроллеру не созданного DecorView. Настройка панелей перенесена после setContentView. Контроллер получается через явно созданный View с проверкой null, а не через Window.getInsetsController. При получении фокуса режим применяется повторно.

Проверен скомпилированный байткод: в screen вызов setContentView предшествует immersive; вызов Window.getInsetsController отсутствует, вызов View.getWindowInsetsController присутствует. Это проверка сборки, а не запуск на One UI 8.

## Выполнено локально

- Java-код и ресурсы собраны с JDK 17, Android SDK 35 и Build Tools 35.0.0; D8 сформировал DEX.
- **28 JVM-проверок прошли:** 15 проверок паролей/календаря и 13 проверок двухминутного срока.
- Проверены возврат на 119 999 мс, блокировка на 120 000 мс, отсутствие продления при повторном pause, сброс срока при возвращении, новый срок после следующего ухода, большой скачок elapsed time при сне устройства и отказ при неожиданном обратном ходе монотонных часов.
- Подпись v3 и выравнивание APK проверены.
- Сертификат совпадает с 0.2.0. Манифест готового APK содержит только разрешение INTERNET и одну MainActivity, без служб/администратора/приёмников. Внутри classes.dex готового APK подтверждено наличие ReturnWindow, immersive и expireSession.
- По исходникам проверены полноразмерный FrameLayout с WebView без внешнего ScrollView, insets для клавиатуры и выреза экрана, скрытие системных панелей и восстановление панелей при возвращении в календарь.
- По исходникам проверены pause/resume существующего WebView, отсутствие уничтожения веб-окна при кратком уходе, скрытие окна в фоне и проверка срока в onStart/onResume до повторного показа. При уничтожении Activity секретный вход не восстанавливается.
- Поворот экрана обрабатывается без пересоздания Activity. Полноэкранное видео использует CustomViewCallback; Back сначала закрывает видео.

## Не проверено на устройстве

Новая версия не запускалась на телефоне или эмуляторе. Реальное отображение на One UI 8, клавиатура Telegram, полноэкранные видео TikTok, реальная приостановка медиа и сохранение позиции конкретными сайтами требуют проверки на устройстве. JVM-тесты подтверждают логику срока, а не выполнение Android lifecycle на конкретной прошивке.

Android может задержать фоновый callback при сне/заморозке. Срок повторно проверяется перед показом страницы, однако физическое выполнение очистки ровно на 120-й секунде не гарантируется. Если ОС выгрузит процесс раньше, потребуется новый дополнительный вход.

Ручная блокировка остаётся немедленной. Cookie сохраняются по умолчанию. При включённой настройке удаления веб-входов очистка запускается при закрытии окна/истечении срока, а не при коротком уходе. Очистка WebStorage запрашивается через API без отдельного callback для каждого типа данных; серверная история не удаляется.

## Сценарии проверки на телефоне

1. Открыть оба сайта: нет заголовка Луны и большого отступа, клавиатура не закрывает поле ввода; крестик возвращает к списку.
2. Уйти на 30–90 секунд и вернуться: остаются тот же сайт и закрытый вход.
3. Уйти больше чем на две минуты, в том числе с выключенным экраном: при возвращении обычный календарь, а не сайт.
4. Выполнить несколько коротких выходов: каждый после успешного возврата получает собственный срок.
5. Проверить поворот, видео и Back. Нажать ручную блокировку: сеанс закрывается сразу.
6. Проверить оба положения переключателя удаления веб-входов; краткий уход не должен выходить из сайта.

Поведение времени основано на [elapsedRealtime](https://developer.android.com/reference/android/os/SystemClock) и повторной проверке срока, учитывающей [задержку Handler во сне](https://developer.android.com/reference/android/os/Handler#postDelayed(java.lang.Runnable,long)).
